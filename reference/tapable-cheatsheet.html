tapable 速查表

参考文档 · 长期复习用 · 依据 官方 README 整理 · 本项目版本 tapable@2.2.1

类名怎么读

每个 Hook 类名由三段信息拼成，读懂三段就读懂全部 10 种：

段取值含义
① 执行模型Sync / AsyncSync 钩子只能用 tap 注册同步函数；Async 钩子三种注册方式都接受
② 并发方式（仅 Async 有）Parallel / SeriesParallel 同时启动全部回调；Series 按注册顺序逐个 await
③ 返回值语义无 / Bail / Waterfall / Loop无＝忽略返回值；Bail＝返回非 undefined 即停止后续；Waterfall＝返回值传给下一个；Loop＝返回非 undefined 则从头再跑

10 种 Hook 一览

类名注册触发一句话语义
SyncHook ★tapcall同步依次调用，忽略返回值
SyncBailHooktapcall同步依次调用，谁返回非 undefined 就短路
SyncWaterfallHooktapcall同步链式，上家返回值是下家入参
SyncLoopHooktapcall返回非 undefined 则该回调重跑
AsyncParallelHooktap / tapAsync / tapPromisecall / callAsync / promise全部并发启动，等齐
AsyncParallelBailHook同上同上并发，任一返回非 undefined 即收尾
AsyncSeriesHook ★同上同上按注册顺序串行，逐个等待
AsyncSeriesBailHook同上同上串行 + 短路
AsyncSeriesWaterfallHook同上同上串行 + 返回值下传
AsyncSeriesLoopHook同上同上串行 + 循环重跑

★ ＝本项目实际使用的两种。AsyncSeriesHook 是本项目绝对主力（持久化、通知都在上面），因为落库必须等前一个插件写完再写下一个，串行即正确顺序。

注册方法三兄弟（Async 钩子通用）

方法回调形态适用
tap(name, fn)同步函数逻辑简单、无 IO
tapAsync(name, (args…, cb) => {})Node 风格回调，最后一个参数是 cb(err)回调风格的老库
tapPromise(name, asyncFn)返回 Promise / async 函数现代 async/await 首选 ★本项目用这种

触发方法三兄弟

方法行为本项目用法
call(…args)同步触发，立即执行完所有回调SyncHook 用（如 errorEncounter）
callAsync(…args, cb)异步触发，全部完成后回调 cb未使用
promise(…args)返回 Promise，await 即等全部回调完成AsyncSeriesHook 全用这种 ★

三条容易踩的坑

  1. 构造参数是参数名数组，不是默认值：new AsyncSeriesHook(['jobInfo', 'matchResult']) 两个字符串只用于文档与报错提示（v2 亦作类型检查依据），不传实参。
  2. Sync 钩子不能 tapPromise：会直接抛错。注册方式必须与钩子类型匹配。
  3. 回调抛错会中断整个触发：promise() 会 reject，因此核心触发处常用 try/catch 包裹（见 geek-auto-start-chat-with-boss/index.mjs:1482-1494）。
