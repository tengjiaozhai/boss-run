核心 API 三个层次

层次API语义本项目用例
网络层page.on('response', cb)持续监听所有响应（旁路）SqlitePlugin 截获 job/detail.json 落库
page.waitForResponse(pred)一次性等待符合条件的响应，返回 Response 对象点击职位后等详情 API；开聊后等 friend/add.json
框架层page.evaluate(expr) 读 __vue__在页面上下文里执行表达式，返回可序列化结果jobList / hasMore / 详情 data / currentJob
page.on('request') + page.off(handler)捕获请求对象，用完即拆监听翻页确认的请求-响应配对
DOM 层page.mouse.wheel({deltaY})派发真实滚轮事件（非 scrollTo 跳转）逐格滚动列表触发懒加载
elementHandle.click()对元素句柄点击点击职位卡片、开聊按钮
page.$ / page.$$查询选择器（单/多）检查"立即沟通"按钮、取卡片列表

三层怎么选（决策树）

需要什么？
├─ 网站自己会请求的数据（XHR/API 响应）
│    └─ 网络层：旁听 page.on('response') 或等待 waitForResponse
│       （保真度最高：服务端原始 JSON，无渲染损失）
├─ 页面已渲染出的状态，但网站有前端框架（Vue/React）
│    └─ 框架层：evaluate 读 __vue__ / 组件内部状态
│       （次选：数据已是结构化，但依赖框架实现细节）
└─ 只有视觉呈现、无 API 无框架数据
     └─ DOM 层：querySelector + 文本解析
        （下策：改版即碎，仅用于操作点击与最小状态确认）

两条实战铁律

  1. 操作用 DOM，读数不走 DOM：点击、滚动必须落 DOM（那是"手"）；取数据优先网络层，其次框架层（那是"眼"）。本项目所有业务数据无一来自 HTML 解析。
  2. 监听用完即拆：page.off(handler)——本仓库翻页监听每次触发后立即注销自己（geek-auto-start-chat-with-boss/index.mjs:925），否则回调会随翻页次数线性堆积。

容易踩的坑

  • page.evaluate 的参数必须是可序列化的——函数会被序列化后送进页面执行，闭包外部变量拿不到（传参用 evaluate(fn, arg)）。
  • waitForResponse(pred) 的谓词从注册那一刻起才生效——先注册再触发操作，顺序反了就永远等不到。本项目点击卡片前先注册（index.mjs:1138-1148）。
  • 同一 URL 可能对应多个响应（重试、预取）——要"这一条"响应就做请求-响应对象配对，别按 URL 猜。
  • __vue__ 是 Vue 2 的实例暴露；Vue 3 生产构建默认没有。框架层直读是脆弱依赖，改版/升级即失效，网络层才耐久。
